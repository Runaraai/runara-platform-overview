Jev vs open Jev models: accuracy, fp4 and serving cost

We benchmarked TypeSafe's hosted Jev 1.14, then self-hosted open-weights Jev models on our own GPUs and ran the identical test. The newest open model, AutoTrust-JEV-27B v1.1, is the closest we have found: ahead on BoolQ and SST-2, level on ARC and Yelp, behind only on MMLU and TruthfulQA. Quantized to fp4 it keeps almost all of that accuracy.

01What we measured

Jev is a decisions model. It does not write text. It receives some context and a structured question (pick one option, answer yes/no, or rate on a scale) and returns probabilities. We therefore measure accuracy from its chosen answer, and how well its confidence matches reality from the probabilities.

04What it costs to serve

We ran v1.1 (bf16) on an RTX PRO 6000 Blackwell and on an H100. The Blackwell is slightly slower but cheaper by the hour, and on cost per token it comes out about 27% cheaper. Both load in about 51 GB, so a single 96 GB (Blackwell) or 80 GB (H100) card serves one instance with headroom. For a bf16 deployment the Blackwell is the better buy.

05Speculative decoding: tried, doesn't fit

We tested whether speculative decoding would speed Jev up. It won't, for two reasons:

  • Nothing to speculate on. Every Jev decision is a single forward pass: one token, read straight off the answer-code logprobs. A draft model has nothing to run ahead on.
  • The engine refuses it. The bidirectional-prefix plugin the model needs rejects speculative decoding outright, so the server will not start with it enabled.

There is no speed to win back here. It would only matter for a chat-style deployment of the base model, which is not what the platform uses.

06Can the platform serve many customers and bill them?

Routing: not today

Each hosted model is a single GPU instance behind a one-to-one auth proxy. There is no gateway or load balancer spreading traffic, so concurrency is capped by that one box. Serving many customers means running several instances behind a real load balancer, which does not exist yet.

Where the clone holds up. ARC Challenge and SST-2 are within noise (−0.6 and −0.7 points, p above 0.2). Yelp is 1.7 points lower and BoolQ 2.4 lower: statistically real, but small.
Where it falls short. MMLU (−8.2), TruthfulQA (−10.3) and the MMLU position test (−10.2) are large gaps. On MMLU, official Jev was right and the clone wrong on 1,412 questions, against only 265 the other way. The clone is also less stable when answer options are reordered.
Against the model card. The JEV-27B card reports a six-benchmark average on par with hosted Jev (84.07% vs 83.85%, self-reported). We did not reproduce that on knowledge-heavy tasks.

12Limits of this report

  • The open-model runs were done by a teammate on rented hardware. We checked that the result files are complete and that the comparison reproduces from them, but we did not re-run the model.
  • JEV-27B was compared against Jev 1.14, while it was distilled from 1.13. Some of the gap may be a version difference.
  • Serving cost is measured for v1.1 in bf16 only. fp4 throughput and memory are not yet measured.
  • v1.1 and fp4 results are reported as accuracy only; confidence intervals and paired significance tests (as in section 10) are not yet published for them.
  • Image understanding is untested for the clone. A vision variant, autotrust/JEV-27B-VL, exists.
  • Three open models were tested (JEV-27B, v1.1 and JEV-35B). JEV-35B is the largest open text model in the family; smaller options such as autotrust/JEV-9B and alibiserikbay/JevK5 (4B) are untested.
Source: Runaraai/Jev-benchmark (code, raw per-question results and reports). Run settings: seed 0, full datasets, decisions API.
