Accuracy benchmark for the Jev model

jevbench

Run one command against OpenRouter, run the same command against a self-hosted deployment, then compare the two with paired statistics.

python 3.10+OpenAI-compatibleresumable12 offline tests passing

Overview

The work is split across two people. Both use the same prompts, answer parsing and sampling settings, so any gap between the two result sets comes from the model or its serving stack and not from the harness.

Jev is a decisions model. On OpenRouter, typesafe/jev-1.14 does not generate text. It answers structured questions (choice, score, noul) through /api/alpha/decisions and returns the chosen option with probabilities and a confidence value. Use --api decisions for Jev. The default --api chat is for ordinary chat models. Decisions mode runs classification tasks only: MMLU, ARC, TruthfulQA, SST-2, BoolQ and your own JSONL. GSM8K, HumanEval and ifeval_lite need generated text and are chat-only.
Part A · you

Official Jev

How correct is the model served by OpenRouter? Run jevbench run with the OpenRouter model slug.

Part B · teammate

Unofficial deployment

Does the self-hosted model match? Same command with --base-url pointing at the server.

Part C · either

Comparison

Is the difference real or noise? jevbench compare answers it per task.

Part D · teammate

Performance

Throughput, latency and time to first token. Separate load-testing tooling, not in this repo.

Quick start

typesafe/jev-1.14 is an alias. Each response names the dated version that served it, for example typesafe/jev-1.14-20261014. The run records it as served_models, so you can see when the alias moves.

# 1. install
python3 -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'

# 2. add your key
cp .env.example .env        # edit: OPENROUTER_API_KEY=sk-or-...

# 3. check the harness works (offline, no key)
pytest -q

# 4. smoke run: 20 samples per task
python -m jevbench run --api decisions --model typesafe/jev-1.14 --limit 20 --out results/smoke

# 5. real run (about $0.00001 per request)
python -m jevbench run --api decisions --model typesafe/jev-1.14 --limit 500 --out results/official

Running benchmarks

# full default suite, provider pinned
python -m jevbench run --model vendor/jev --provider SomeProvider --limit 500 --out results/official

# selected tasks, whole dataset (0 = no limit)
python -m jevbench run --model vendor/jev --tasks gsm8k,humaneval --limit 0

# determinism: three identical requests per question
python -m jevbench run --model vendor/jev --tasks mmlu --repeats 3 --out results/consistency

# reasoning model: leave room for thinking tokens
python -m jevbench run --model vendor/jev --max-tokens 8192 --concurrency 8

# your own prompts
python -m jevbench run --model vendor/jev --tasks "" --custom my_eval.jsonl

Custom task formats

In decisions mode each line holds the state, the questions as you would send them, and the expected answers. A row is correct only if every expected answer matches: option key for choice, integer for score, true or false for noul.

{"id": "bike-1", "state": ["Listing: vintage red bicycle, heavy rust"],
 "questions": {"category": {"type": "choice", "instructions": "Which category fits?",
                "criteria": {"bikes": "Complete bicycles", "parts": "Components"}},
               "condition": {"type": "score", "instructions": "How worn is the item?",
                "criteria": ["Like new", "Light wear", "Heavy wear"]}},
 "expected": {"category": "bikes", "condition": 2}}

In chat mode, use these lines:

{"id": "q1", "prompt": "What is the capital of France?", "reference": "Paris", "match": "contains"}
{"prompt": "Reply with only YES or NO: is 7 prime?", "reference": "yes", "match": "exact"}
{"prompt": "Give a date in ISO format.", "reference": "\\d{4}-\\d{2}-\\d{2}", "match": "regex"}
Resuming. Every response is saved as it arrives. After a crash or Ctrl-C, re-run the same command. Finished samples are skipped and failed ones are retried.

Comparing two deployments

Your teammate runs the identical command against the self-hosted server. Only the URL and model name change. A self-hosted endpoint needs no API key; if yours does, add --api-key-env <VAR>. The deployment must accept the same request format as the OpenRouter decisions endpoint.

python -m jevbench run \
    --api decisions --decisions-url http://<host>:8000/<decisions-path> \
    --model <served-model-name> \
    --limit 500 --seed 0 --out results/unofficial

python -m jevbench compare results/official results/unofficial \
    --out reports/official_vs_unofficial.md

Before benchmarking a self-hosted endpoint, run python -m jevbench check --decisions-url <url> --model <name>. It validates the request and response format (see docs/decisions-api-spec.md).

How to read it

CI excludes 0, p < 0.05The deployments genuinely differ on that task.
CI includes 0No evidence of a difference at this sample size. That is not proof they are identical. Raise --limit.
Low agreement, similar accuracyPossibly a different model or heavy quantization that happens to score alike.

 "finish_reason": "stop", "usage": {"completion_tokens": 211},
 "latency_s": 3.4, "provider": "SomeProvider", "error": null}

summary.json stores the model, base URL, provider pin, temperature, seed, limit and timestamp, so each run describes itself. Raw responses are kept so parse failures can be audited by hand.

Methodology

  • Pin the provider. OpenRouter can route one slug to upstreams with different quantization or serving stacks. Pass --provider and check the providers field afterwards. Fallbacks stay off unless requested.
  • Temperature 0 and a fixed seed are the defaults. GPU serving still is not always bit-exact, so measure it with --repeats 3.
  • Same --seed and --limit on both sides. This is what makes the paired comparison valid.
  • Check parse_fail_rate and truncated_rate first. Above a few percent, raise --max-tokens or read the raw responses. A low score may be a formatting artifact.
  • Contamination. These datasets are public, so absolute scores run optimistic. The official-versus-unofficial comparison stays valid. Use custom with private prompts for a clean signal.

How many samples

The worst-case 95% interval on accuracy is about ±1/√n. A 2-point gap needs thousands of samples, or the paired test, which works well when the two models mostly agree.

Extending

A new benchmark is one small class. Register it in REGISTRY in jevbench/tasks/__init__.py. Multiple-choice sets can subclass MCTask and implement only rows().

from .base import Sample, Task, subsample

class MyTask(Task):
    name = "my_task"
    max_tokens = 512

    def load(self, limit, seed):
        rows = [...]
        return [Sample(id=f"my-{i}", prompt=rows[i]["q"], target=rows[i]["a"])
                for i in subsample(len(rows), limit, seed)]

    def score(self, s, text):
        pred = text.strip() or None      # None counts as unparseable
        return {"correct": pred == s.target, "pred": pred}

Troubleshooting and caveats

SymptomFix
HTTP 400 "is a decisions model"You used --api chat. Jev needs --api decisions.
HTTP 402 Insufficient creditsAdd credits on the OpenRouter account.
OPENROUTER_API_KEY is not setCreate .env from .env.example, or export the variable.
Many HTTP 429Lower --concurrency. The client already retries up to 6 times with backoff.
High truncated_rateRaise --max-tokens. Reasoning models often need 4k to 16k.
High parse_fail_rateRead raw responses in the .jsonl. The model may ignore the Answer: X format.
error_rate above 0Re-run the same command. Failed items are retried.
Slow first runHuggingFace datasets download once, then are cached.
Security. humaneval executes model-generated Python on your machine (subprocess, 15 s timeout, no network isolation or memory cap). Use Docker or a VM for models you do not trust, or skip it with --tasks mmlu,gsm8k,arc_challenge,truthfulqa,ifeval_lite.
Cost and assumptions. Decisions requests cost about $0.00001 each, so 500 samples × 5 tasks is a few cents. A noul answer is read as P(true) with a 0.5 threshold. A score answer's number is a continuous expected value, so the prediction is the most probable level. With --limit 0 the large tasks keep a cap (Yelp 2,000, ScienceQA 500, mmlu_perm 500 questions). The API rejects images with a short side under about 280 px or a long side over about 1,500 px, so ScienceQA images are resized into range. Temperature and seed are not sent in decisions mode, so use --repeats 3 to measure stability.
