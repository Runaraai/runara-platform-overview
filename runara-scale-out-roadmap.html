What the code does today

Read from the repo, so the plan builds on what exists rather than starting over.

Evaluate already scales to zero, on GCP only

Each hosted model boots its own GCE VM (convex/models.ts). An idle sweep watches heartbeats, but idle auto-stop was recently switched off, so users stop models by hand.

Every deployment is one dedicated machine

A VM, pod or container per user, running vLLM or SGLang. Replicas, load balancing and request-based scaling don’t exist yet.

No Kubernetes anywhere

No clusters, Helm or Terraform. Infra is Packer images, cloud APIs called from Convex actions, and crons that run every 1 to 5 minutes.

Eight clouds, six with BYOC

AWS, GCP, Azure (beta), Lambda, Vast and RunPod have BYOC. Scaleway and Koyeb are managed only. Analyzer “Deploy” supports only AWS, GCP, Lambda and Vast.

Who builds what

Start Kubernetes autoscaling first, because serverless sits on top of it.

Kubernetes autoscaling

2 engineers

The foundation. Start it first, because serverless sits on top of it.

Scope

  • Create a cluster in the customer’s account (BYOC) or Runara’s (managed), with GPU node pools.
  • Scale replicas on vLLM metrics: waiting requests, KV-cache usage and time to first token. KEDA or HPA drives it.
  • The cluster autoscaler adds and removes GPU nodes, capped by budget and quota.
  • An in-cluster Runara agent posts state back to Convex HTTP endpoints. Convex stays the source of truth.
  • A VM-level autoscaler for marketplaces with no managed K8s (Vast, RunPod, Lambda). It reuses the AWS warm-pool pattern.
Done whenA deployment from any tab gets min/max replicas, scales under load and scales back down.

Serverless deployments

2 engineers

Make the Evaluate experience a product: pick a model, get an endpoint, pay only for use.

Scope

  • One shared gateway that checks rk_live_ keys, queues requests and routes them to warm replicas. It replaces the auth proxy on each box.
  • Usage metering into Stripe, priced per token or per GPU-second.
  • Scale-to-zero with a small warm pool for popular models.
  • Cold-start work: cached weights, the RunAI streamer and pre-baked images, aimed at under 60 s for 70B-class models.
  • Move the four Evaluate models onto it first, then open it to customer models and BYOC.
Done whenA customer deploys a model serverless, it idles at $0, and the first request wakes it.

Four more BYOC clouds

2 engineers

Each engineer takes two clouds. After that, they join the K8s team to stand up a cluster on each new cloud.

Scope per cloud

  • An adapter (convex/<cloud>.ts) wired into the launch and terminate dispatch in experiments.ts.
  • BYOC credentials (<cloud>Byoc.ts) and a form in Settings → Cloud setup.
  • A GPU image built with Packer, a pricing fetcher and a crawler adapter.
  • Entries in cloud-providers.ts and the Analyzer deploy mapping.
Done whenA customer connects their own account, the Analyzer recommends that cloud, and one click deploys there.

The four clouds to add, and why

Each one has on-demand GPUs, a usable API and a managed Kubernetes service. That last point matters, because it lets the autoscaling and BYOC workstreams use the same cluster code.

Vultr

A100, H100 and AMD MI300X with a simple REST API. A quick first integration.

K8s: VKE

DigitalOcean

H100 GPU Droplets. Popular with the startups already in our funnel.

K8s: DOKS

CoreWeave

The largest GPU-native cloud, built around Kubernetes. H100, H200 and B200.

K8s: CKS

Oracle OCI

Large H100, H200 and B200 bare-metal fleet. Enterprises often have credits there.

K8s: OKE

Alternates if one falls through: Nebius, Crusoe, Hyperstack. Smaller cleanups for the same team: take Azure BYOC out of beta and add BYOC for Scaleway.
